- (2026-09-24) Streaming camera on the Linux desktop (DJI Osmo Pocket 4, webcam mode): in OBS it must stay a **Media Source** (input `/dev/v4l/by-id/usb-DJI_OsmoPocket4-*-video-index0`, input format `v4l2`, FFmpeg options `input_format=mjpeg video_size=1920x1080 framerate=30`), never a "Video Capture Device (V4L2)" source. Cause, measured: at 1080p MJPEG the camera negotiates a 622,080-byte max frame (its descriptor says 1,843,200), Linux's uvcvideo trusts the smaller figure, so a detailed frame overflows and its tail arrives as an unflagged broken JPEG about once every 1–2 min; OBS's V4L2 source stops capturing on the first frame it cannot decode, which was the "freezes after 40 s – 3 min" fault. The Media Source's FFmpeg decoder skips the fragment: 30 min with no freeze on 2026-09-24, while a raw control recording straight after showed the camera still sending 14 flagged frames and 1 unflagged fragment per 5 min. Both scene collections (GameDev, GameDev-TikTok) were converted; backups in `~/.config/obs-studio/basic/scenes/backup-before-dji-fix-20260924/`. Limit of this lesson: it is this camera's firmware plus OBS 32.1 plus kernel 7.0; a camera firmware update, an OBS fix to the V4L2 source, or a uvcvideo quirk for 2ca3:0023 would each remove the need — re-test with the V4L2 source before assuming it is still required.
